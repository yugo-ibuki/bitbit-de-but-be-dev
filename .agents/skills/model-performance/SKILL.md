# Model Performance

`projects/model-performance/` は、AIモデルが生成したゲームなどの成果物を実際に動かし、その能力や品質を観察するための実験領域である。

## 進め方

1. 1つの実験を1つのサブディレクトリに分ける。既存実験を変更する場合は、その目的と記録を壊さない。
2. 着手前に、依頼された成果物、対象モデル、確かめたい能力や品質を把握する。モデル名や設定を取得できない項目は「不明」とし、推測で補完しない。
3. 実際に入力したプロンプトと追加指示は原文のまま残す。分かる範囲で、モデル識別子、推論設定、利用ツール、時間・回数など結果に影響する生成条件も記録する。
4. 成果物を作成・実行し、評価する前に観察可能な受け入れ基準を定める。実験に適した方法を選び、スコア、専用スクリプト、固定の技術構成を必須にしない。
5. ビルド、テスト、実操作など必要な確認を行い、実行したコマンド、観察結果、失敗を証拠とともに残す。
6. 計画、試行、観察済み、完了を区別する。ファイル生成、進捗表示、終了コードだけを、動作や品質の確認済みという根拠にしない。

## 評価と比較

- 合否や評価は、事前に定めた基準と実際の観察に結び付ける。未確認の動作、点数、成功を作らない。
- 定量スコアが目的に合わなければ、観察事項と評価基準を記録するだけでよい。
- モデル間の比較は、プロンプト、初期状態、制約、確認方法など主要条件を揃えられる場合に限る。差がある場合は比較結果ではなく条件差として明記する。
- 構成や実装言語は各実験の目的に合わせる。再現と検証に必要な情報だけを残し、不要なひな型や補助ファイルを増やさない。
