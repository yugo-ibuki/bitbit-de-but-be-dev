# 積み立てゲーム 初期版設計

## 目的

ブラウザ上の3D空間に複数種類の物体を自由に積み上げ、完成した山を一気に崩す体験を提供する。初期版では、精密な建築よりも「置く」「重なる」「壊す」「崩れ落ちる」の一連の手触りを優先する。

## スコープ

新しい独立プロジェクトを `games/tsumitate-game/` に作成する。対象はPCブラウザを中心とし、スマートフォンのタップ操作にも対応する。

初期版に含める機能は以下とする。

- 箱、球、円柱の3種類から投下する物体を選択できる
- 地面または既存物体をクリック／タップすると、その地点の少し上から選択中の物体を落とせる
- 重力、衝突、反発、摩擦によって物体が自然に積み重なる
- 物体には鮮やかな色と小さなランダム回転を付ける
- カメラをドラッグで回転し、ホイールまたはピンチでズームできる
- 「破壊する」操作で、積み上げた物体群の中心から外向きの衝撃を加えられる
- 破壊時に画面揺れと衝撃波を表示する
- 「もう一度積む」操作で動的な物体をすべて消し、初期状態へ戻せる
- 現在の物体数と上限を表示する
- 操作方法を画面内に短く表示する

初期版には、スコア、ステージ、保存、オンライン機能、音声、ユーザー作成モデルの読み込みは含めない。

## 技術構成

- Vite
- TypeScript
- Three.js
- Rapier (`@dimforge/rapier3d-compat`)
- Vitest

Reactは導入せず、DOM UIとゲームループを小さなモジュールで直接構成する。初期版の依存関係と抽象化を抑えながら、描画と物理演算は実績のあるライブラリへ任せる。

## モジュール構成

### `Game`

Three.jsのシーン、カメラ、レンダラー、Rapierのワールド、固定タイムステップを所有する。アニメーションループ内で物理世界を進め、各剛体の位置と回転を対応するメッシュへ同期する。

### `ObjectFactory`

箱、球、円柱について、Three.jsのジオメトリとRapierのコライダーを同じ寸法定義から生成する。生成済みオブジェクトは、メッシュ、剛体、種類を一組として管理する。

### `PlacementController`

ポインター位置からレイを飛ばし、地面または配置済みメッシュとの交点を得る。交点の上方に投下位置を決め、選択中の種類を生成する。カメラ操作中のドラッグは配置と判定しない。

### `DestructionController`

動的物体の平均位置を爆心地として求める。各物体へ、爆心地からの方向と距離に応じた外向きインパルスとランダムな回転力を与える。物体がない場合は何もしない。

### `UIController`

物体選択、破壊、リセット、個数表示、上限表示、初期化エラー表示を担当する。ゲーム内部へはコールバックで操作を渡し、Three.jsやRapierへ直接依存しない。

## データフロー

1. アプリ起動時にRapierを初期化し、地面、照明、カメラ、UIを作る。
2. ユーザーが物体種類を選び、舞台をクリック／タップする。
3. `PlacementController` が投下位置を計算し、`ObjectFactory` がメッシュと剛体を生成する。
4. `Game` が固定タイムステップで物理演算を進め、レンダリングフレームごとに表示を同期する。
5. 「破壊する」で `DestructionController` が全動的物体へインパルスを与える。
6. 画面外へ落ちた物体はゲームループ内の整理処理で削除する。
7. 「もう一度積む」で全動的物体をThree.jsとRapierの両方から削除する。

## ゲームルールと制約

- 動的物体の上限は100個とする
- 上限到達時は新規生成せず、UI上で短く通知する
- 画面外判定は高さが `-20` を下回った場合とする
- 投下開始位置は交点から物体の大きさを考慮して上方へずらす
- 破壊力は距離に応じて弱くするが、最遠の物体にも崩壊を起こせる最低値を持たせる
- 破壊操作は何度でも実行できる
- リセット後もカメラ位置と選択中の物体種類は維持する

## ビジュアル設計

夕暮れを思わせる暗いグラデーション背景の中央に、円形のジオラマ風舞台を置く。環境光、主光源、補助光源を組み合わせ、物体と地面には影を表示する。物体は形ごとに識別しやすい鮮やかな色群からランダムに選ぶ。

UIはゲーム画面を隠しすぎない半透明パネルとし、物体選択を上部、破壊とリセットを下部または右下に配置する。「破壊する」は暖色で大きく表示し、通常操作との違いを明確にする。

破壊時の衝撃波は、爆心地から拡大して消える半透明リングで表現する。カメラ揺れは短時間かつ小さくし、操作不能や酔いを起こしにくい強さにする。

## エラー処理と性能

- WebGLまたはRapierの初期化に失敗した場合、ゲーム画面上に再読み込みを案内する
- 物体数を100個に制限し、生成済みジオメトリとマテリアルを種類・色単位で再利用する
- ウィンドウのリサイズ時にカメラのアスペクト比とレンダラーサイズを更新する
- 物体削除時はThree.jsメッシュとRapier剛体を必ず両方削除する
- `requestAnimationFrame` の経過時間が大きい場合は、物理ステップへ渡す時間を上限付きにする

## テスト方針

Vitestで描画環境を必要としないロジックを検証する。

- 物体種類ごとの寸法定義と投下オフセット
- オブジェクト上限の判定
- 爆心地となる平均位置の計算
- 距離に応じた破壊インパルスの方向と強さ
- 画面外判定

加えて、以下を完了条件とする。

- TypeScriptの型チェックが成功する
- Vitestの全テストが成功する
- Viteのプロダクションビルドが成功する
- 実ブラウザで箱、球、円柱を積める
- 実ブラウザで破壊操作により物体が散らばり、落下し、崩れる
- 実ブラウザでリセット後に再び積み始められる
- デスクトップ幅とモバイル相当幅でUIの主要操作が画面内に収まる

## 完成条件

`games/tsumitate-game/` 単体で依存関係をインストールし、`npm run dev` でブラウザから遊べること。ユーザーが3種類の物体を任意位置へ投下して積み上げ、破壊ボタンで物理的に崩し、リセットして繰り返せることを初期版の完成とする。
