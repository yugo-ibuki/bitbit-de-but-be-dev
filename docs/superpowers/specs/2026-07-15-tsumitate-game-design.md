# 積み立てゲーム 初期版設計

## 目的

ブラウザ上の3D空間に複数種類の物体を自由に積み上げ、完成した山を一気に崩す体験を提供する。初期版では、精密な建築よりも「置く」「重なる」「壊す」「崩れ落ちる」の一連の手触りを優先する。

## スコープ

新しい独立プロジェクトを `games/tsumitate-game/` に作成する。対象はPCブラウザを中心とし、スマートフォンのタップ操作にも対応する。

初期版に含める機能は以下とする。

- 箱、球、円柱の3種類から投下する物体を選択できる
- 地面または既存物体をクリック／タップすると、その地点の少し上から選択中の物体を落とせる
- 重力、衝突、反発、摩擦によって物体が自然に積み重なる
- 物体には鮮やかな色と小さなランダム回転を付ける
- カメラをドラッグで回転し、ホイールまたはピンチでズームできる
- 「破壊する」操作で、積み上げた物体群の中心から外向きの衝撃を加えられる
- 積み上げ中は円周上の透明な壁が物体を舞台内に留め、破壊時に壁が消える
- 破壊時に画面揺れと衝撃波を表示する
- 「もう一度積む」操作で動的な物体をすべて消し、初期状態へ戻せる
- 現在の物体数と上限を表示する
- 操作方法を画面内に短く表示する

初期版には、スコア、ステージ、保存、オンライン機能、音声、ユーザー作成モデルの読み込みは含めない。

## 技術構成

- Vite
- TypeScript
- React
- Three.js
- React Three Fiber (`@react-three/fiber`)
- React Three Drei (`@react-three/drei`)
- React Three Rapier (`@react-three/rapier`)
- Vitest
- React Testing Library

Reactで画面全体の状態とUIを構成し、React Three FiberでThree.jsのシーンを宣言的に組み立てる。物理演算はReact Three Rapierへ任せ、カメラ操作にはDreiの `OrbitControls` を利用する。初期版ではZustandなどの外部状態管理は導入せず、Reactのstate、context、refで完結させる。

## モジュール構成

### `App`

ゲームフェーズ、選択中の物体種類、生成済み物体の記述データ、個数、通知を所有する。HUDからの操作と3Dシーンからの配置要求を受け取り、ゲーム全体の状態を一方向に更新する。

### `GameScene`

React Three Fiberの `Canvas` 内に、カメラ、照明、舞台、Rapierの物理世界、動的物体、衝撃波を配置する。フレーム更新では画面外へ落ちた物体の検出とカメラ揺れだけを扱う。

### `ContainmentWall`

舞台の円周に沿って薄い直方体コライダーを並べ、積み上げ中の物体が円外へ落ちるのを防ぐ。破壊操作と同時にアンマウントし、リセット時に再生成する。壁自体は描画せず、舞台の発光リングだけを視覚的な境界として使う。

### `StackingObject`

箱、球、円柱の見た目とRapierの剛体・コライダーを、同じ寸法定義から描画する。各物体は安定したIDを持ち、親コンポーネントから種類、位置、色、初期回転を受け取る。

### `PlacementSurface`

地面と配置済み物体のポインターイベントから交点を受け取り、その少し上を投下位置として `App` へ通知する。ポインターの移動量を記録し、カメラ操作中のドラッグは配置と判定しない。

### `DestructionEffect`

登録された剛体refから平均位置を求め、各剛体へ距離に応じた外向きインパルスとランダムな回転力を与える。爆心地へ一時的な衝撃波を表示し、カメラ揺れの開始を通知する。物体がない場合は何もしない。

### `GameHud`

物体選択、破壊、リセット、個数表示、上限表示、操作説明、初期化エラー表示を担当する通常のReactコンポーネント。3Dライブラリへ直接依存せず、propsで状態と操作コールバックを受け取る。

## データフロー

1. `App` がUI状態を初期化し、`Canvas` と `GameHud` を描画する。
2. `GameScene` 内でReact Three Rapierを初期化し、地面、照明、カメラを作る。
3. ユーザーが物体種類を選び、舞台をクリック／タップする。
4. `PlacementSurface` が投下位置を計算して `App` へ通知し、React stateへ新しい物体データを追加する。
5. `StackingObject` が物体データからメッシュと剛体を描画し、React Three Rapierが物理演算と表示同期を行う。
6. 「破壊する」で `DestructionEffect` が登録済みの全剛体へインパルスを与える。
7. 破壊操作と同時に `ContainmentWall` をアンマウントし、物体が円外へ飛べるようにする。
8. 画面外へ落ちた物体はIDを `App` へ通知し、stateから削除することでシーンと物理世界の両方からアンマウントする。
9. 「もう一度積む」で物体データを空にし、円周壁を再生成する。

## ゲームルールと制約

- 動的物体の上限は100個とする
- 上限到達時は新規生成せず、UI上で短く通知する
- 画面外判定は高さが `-20` を下回った場合とする
- 投下開始位置は交点から物体の大きさを考慮して上方へずらす
- 破壊力は距離に応じて弱くするが、最遠の物体にも崩壊を起こせる最低値を持たせる
- 破壊操作は何度でも実行できる
- リセット後もカメラ位置と選択中の物体種類は維持する

## ビジュアル設計

夕暮れを思わせる暗いグラデーション背景の中央に、円形のジオラマ風舞台を置く。環境光、主光源、補助光源を組み合わせ、物体と地面には影を表示する。物体は形ごとに識別しやすい鮮やかな色群からランダムに選ぶ。

UIはゲーム画面を隠しすぎない半透明パネルとし、物体選択を上部、破壊とリセットを下部または右下に配置する。「破壊する」は暖色で大きく表示し、通常操作との違いを明確にする。

破壊時の衝撃波は、爆心地から拡大して消える半透明リングで表現する。カメラ揺れは短時間かつ小さくし、操作不能や酔いを起こしにくい強さにする。

## エラー処理と性能

- WebGLまたはRapierの初期化に失敗した場合、ゲーム画面上に再読み込みを案内する
- 物体数を100個に制限し、ジオメトリとマテリアル定義を種類・色単位で再利用する
- `Canvas` のレスポンシブ機能で、ウィンドウサイズに合わせてカメラとレンダラーを更新する
- 物体削除はReact stateからの除去に統一し、メッシュと剛体を同時にアンマウントする
- 物体コンポーネントは安定したIDで管理し、不要な再生成を避ける

## テスト方針

Vitestで描画環境を必要としないロジックを検証する。

- 物体種類ごとの寸法定義と投下オフセット
- オブジェクト上限の判定
- 爆心地となる平均位置の計算
- 距離に応じた破壊インパルスの方向と強さ
- 画面外判定

React Testing LibraryでHUDを検証する。

- 物体種類の選択状態
- 個数と上限の表示
- 破壊・リセット操作のコールバック
- 上限到達時と初期化失敗時の通知

加えて、以下を完了条件とする。

- TypeScriptの型チェックが成功する
- Vitestの全テストが成功する
- Viteのプロダクションビルドが成功する
- 実ブラウザで箱、球、円柱を積める
- 実ブラウザで破壊操作により物体が散らばり、落下し、崩れる
- 実ブラウザでリセット後に再び積み始められる
- デスクトップ幅とモバイル相当幅でUIの主要操作が画面内に収まる

## 完成条件

`games/tsumitate-game/` 単体で依存関係をインストールし、`npm run dev` でブラウザから遊べること。ユーザーが3種類の物体を任意位置へ投下して積み上げ、破壊ボタンで物理的に崩し、リセットして繰り返せることを初期版の完成とする。
