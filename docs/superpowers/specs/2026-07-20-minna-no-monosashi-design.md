# 「みんなのものさし」MVP設計

## 目的

身近な問いに答えた直後、自分の答えと他の参加者の答えを見比べられるオンライン体験を提供する。参加者は「自分にとって普通だと思っていた境界」と、他の人の境界の違いを、説明や議論を強制されずに楽しめる。

参考にするのは、西武渋谷店「はてな展」が掲げる、身近な問いを通して一人ひとりの普通や価値観の違いに触れ、自分の回答とみんなの回答を見比べるという体験である。名称、ロゴ、質問文、文章表現、画面デザインは複製せず、独自プロダクトとして構成する。

仮称を「みんなのものさし」とする。

## スコープ

新しい独立プロジェクトを `games/minna-no-monosashi/` に作成する。スマートフォンを主対象とし、PCでも主要操作が完結するレスポンシブWebアプリとする。MVPは日本語のみだが、公開URLには地域制限を設けず、世界中からアクセスできるようにする。

MVPに含める機能は以下とする。

- 公開中・終了済みの質問ブロック一覧
- 共有可能なブロック個別URL
- 1ブロックにつき1〜10問の単一選択質問
- 各質問に2個以上の可変数の選択肢
- 1問ずつ回答し、回答直後に人数と割合を表示する参加フロー
- 途中離脱後の同一端末での再開
- 全問回答後の振り返り画面
- ログイン不要の匿名参加
- 同じ端末から同じ質問への回答を1回に制限
- 管理者ログイン
- ブロック、質問、選択肢の作成、並べ替え、複製、公開、終了
- 下書き、公開中、終了済みのライフサイクル
- サンプルの10問ブロック
- 基本的なレート制限と入力検証
- Cloudflareへのデプロイと本番相当環境での動作確認

MVPに含めないものは以下とする。

- 一般参加者によるブロック作成
- 参加者アカウント、SNSログイン、プロフィール
- 複数管理者や管理者権限管理
- コメント、チャット、自由記述回答
- 複数選択回答
- 回答の変更、取り消し
- ランキング、課金、多言語化
- 厳密な本人確認、端末をまたいだ重複防止
- 元イベントの名称、ロゴ、質問、ビジュアルの複製

## 採用する技術構成

- TypeScript
- React
- Vite
- Cloudflare Workers Static Assets
- Hono
- Cloudflare D1
- Cloudflare Workers Rate Limiting binding
- Vitest
- React Testing Library
- Cloudflare Workers Vitest integration
- Playwright
- Wrangler

React/Viteで参加者画面と管理画面を構築し、同じCloudflare Workerで静的ファイルとHono APIを配信する。永続データはD1へ保存する。単一のデプロイ単位でフロントエンド、API、DB接続を管理し、MVPの運用対象を増やさない。

### 比較した代替案

React/Vite + Supabaseは、認証や管理機能を拡張しやすい一方、CloudflareとSupabaseの両方を運用する必要がある。Next.js + PostgreSQLは一般的で拡張性が高い一方、今回の小規模な匿名投票体験には構成が重い。既存リポジトリにCloudflare向けWebアプリの先例があり、世界公開、匿名回答、即時集計を少ない構成要素で実現できるため、Cloudflare Workers + D1を採用する。

## 画面とルート

### 公開画面

- `/`：公開中ブロックと終了済みブロックの一覧
- `/play/:slug`：ブロックの説明、質問数、総参加者数、開始または再開
- `/play/:slug/questions/:position`：質問への回答
- `/play/:slug/questions/:position/result`：回答直後の集計
- `/play/:slug/summary`：全問回答後の振り返り
- `/results/:slug`：終了済みブロックの全体集計

公開中ブロックでは、各質問の選択肢別集計を、その質問へ回答した端末だけが閲覧できる。回答前にはブロック全体の総参加者数だけを表示する。終了済みブロックは新規回答を受け付けないため、例外として全質問の集計を誰でも閲覧できる。

### 管理画面

- `/admin/login`：管理者ログイン
- `/admin`：状態別のブロック一覧
- `/admin/blocks/new`：ブロック作成
- `/admin/blocks/:id/edit`：下書き編集
- `/admin/blocks/:id/preview`：参加者表示のプレビュー
- `/admin/blocks/:id/results`：管理者向け全体集計

公開中・終了済みブロックの詳細画面には「複製して下書きを作る」を設ける。公開済み内容を直接編集する操作は提供しない。

## 参加者フロー

1. 初回アクセス時にブラウザの暗号学的乱数から匿名端末トークンを生成し、`localStorage`へ保存する。
2. 一覧または共有URLからブロックを開く。
3. ブロック内に未回答の質問があれば、最初の未回答位置から開始または再開する。
4. 画面には一度に一つの質問と選択肢だけを表示する。
5. 選択後に確認ボタンを押すまで回答は送信しない。
6. 回答が保存されたら、同じ画面遷移内で自分の選択、選択肢別の人数・割合、総回答数を表示する。
7. 「次の質問へ」で次の未回答質問へ進む。
8. 全問回答後、質問、自分の回答、その質問の全体集計をまとめて振り返る。
9. `localStorage`が利用できない場合は現在のタブ内だけで動作する一時トークンを使い、再読み込み後は進捗を復元できないことを回答前に知らせる。

回答送信後は選択肢を変更できない。別タブや通信再試行から同時に送信されても、DBの一意制約を最終的な重複防止とする。

## 管理者フロー

1. 環境変数で設定された単一管理者パスワードを使ってログインする。
2. タイトル、説明、URLスラッグを入力し、下書きブロックを作成する。
3. 1〜10個の質問を追加し、質問文と2個以上の選択肢を入力する。
4. 質問と選択肢を並べ替える。
5. プレビューでスマートフォン相当の参加画面を確認する。
6. 検証に成功した下書きを公開する。
7. 公開中ブロックの参加者数と質問別集計を管理画面から確認する。
8. 回答受付を終える場合は、公開中ブロックを終了済みにする。

状態遷移は `draft -> published -> closed` の一方向とする。下書きは編集・削除できる。公開中と終了済みは質問、選択肢、順番、スラッグを変更・削除できない。内容を修正または再利用する場合は、新しいIDとスラッグを持つ下書きへ複製する。終了済みブロックを再公開する操作は提供しない。

## 入力ルール

- ブロックタイトル：1〜80文字
- ブロック説明：0〜400文字
- スラッグ：3〜64文字、小文字英数字とハイフンのみ、全ブロックで一意
- 質問文：1〜200文字
- ブロック内の質問数：1〜10問
- 選択肢ラベル：1〜80文字
- 各質問の選択肢数：2個以上。質問ごとに追加・削除でき、固定数にしない
- 空白だけの値は禁止
- 同じ質問内で正規化後に同一となる選択肢は禁止
- 並び順はブロック内、質問内で重複しない整数として保存する

管理画面とAPIの両方で同じドメインルールを検証する。公開操作ではブロック全体を再検証し、一つでも不正な質問があれば公開しない。

### `blocks`

- `id`
- `slug`
- `title`
- `description`
- `status`：`draft | published | closed`
- `created_at`
- `updated_at`
- `published_at`
- `closed_at`

### `questions`

- `id`
- `block_id`
- `prompt`
- `position`
- `created_at`

`block_id, position` を一意にする。

### `options`

- `id`
- `question_id`
- `label`
- `position`
- `created_at`

`question_id, position` を一意にする。

### `responses`

- `id`
- `block_id`
- `question_id`
- `option_id`
- `voter_key_hash`
- `created_at`

`question_id, voter_key_hash` を一意にする。`block_id`は集計と整合性検証を単純にするため明示的に保持する。外部キーとAPI検証により、質問がブロックへ、選択肢が質問へ属することを保証する。質問別集計用に `question_id, option_id`、ブロック参加者集計用に `block_id, voter_key_hash` のインデックスを持つ。

管理者セッションはDBへ保存せず、短い有効期限を持つ署名付きHttpOnly Cookieとして扱う。

## 匿名端末IDとプライバシー

ブラウザが生成した匿名端末トークンの生値をDBへ保存しない。Workerはサーバー側Secretを使ったHMACでトークンを不可逆な `voter_key_hash` へ変換し、その値だけを保存する。氏名、メールアドレス、プロフィール、位置情報、User-Agent、生のIPアドレスは回答レコードへ保存しない。

端末トークンを削除した場合、別ブラウザ、別端末、プライベートブラウジングでは別参加者として扱われる。MVPの「1人1回」は本人単位ではなく端末のブラウザ保存領域単位であり、画面上の説明にも明記する。

## 回答登録と集計

回答APIは次の順序で処理する。

1. リクエスト形式と文字列長を検証する。
2. レート制限を確認する。
3. ブロックが `published` であることを確認する。
4. 質問がブロックへ、選択肢が質問へ属することを確認する。
5. 匿名端末トークンをHMAC化する。
6. 一意制約を伴う `responses` のINSERTを実行する。
7. 質問単位の集計と、保存された自分の回答を返す。

同じ質問・同じ端末・同じ選択肢の再送は、ネットワーク再試行として成功扱いにし、既存回答と現在の集計を返す。同じ質問へ別の選択肢を再送した場合は `409 ANSWER_LOCKED` を返し、既存回答を変更しない。

各選択肢の人数は `responses` を選択肢ごとに集計する。割合は質問の総回答数を分母とする。表示する整数割合は最大剰余法で配分し、選択肢の割合合計が100%になるようにする。回答が0件の場合は全選択肢を0%とする。ブロックの総参加者数は、そのブロックで1問以上回答した `voter_key_hash` の重複を除いた件数とする。

## API境界

公開APIは、ブロック一覧、ブロック詳細、端末ごとの進捗、回答登録、回答済み質問の結果、終了済みブロックの結果を提供する。匿名端末トークンはURLへ含めず、HTTPSのリクエストボディまたは専用ヘッダーで送る。

管理APIは、ログイン、ログアウト、下書きCRUD、プレビュー、公開、終了、複製、全体集計を提供する。状態を変更する管理APIは、有効な管理者セッション、SameSite Cookie、Origin検証、CSRFトークンを要求する。

APIエラーは次の共通形式を使う。

```json
{
  "error": {
    "code": "ANSWER_LOCKED",
    "message": "この質問には回答済みです"
  }
}
```

UIはHTTPステータスだけでなく安定したエラーコードで分岐する。

## セキュリティと迷惑送信対策

- 管理者パスワードは平文でリポジトリや通常の環境変数へ置かず、強いパスワードハッシュをCloudflare Secretとして設定する
- 管理者セッションCookieは `HttpOnly`、`Secure`、`SameSite=Strict` とする
- セッション署名Secretと端末IDのHMAC Secretを分離する
- 管理画面の状態変更にはCSRF対策とOrigin検証を行う
- 全入力をサーバー側で検証し、SQLはD1のパラメータ化クエリだけを使う
- 参加者が入力した文字列をHTMLとして解釈しない
- Content Security Policyなどの基本的なセキュリティヘッダーを返す
- 回答APIへCloudflare Workers Rate Limiting bindingを適用する
- レート制限キーには生のIPを永続化せず、日単位で変化するSecret付きハッシュと匿名端末キーを使う
- 管理者ログインにも回答APIより厳しいレート制限を適用する
- アプリケーションログへ端末トークン、生IP、管理者パスワードを出力しない

この対策は大量送信を抑制するが、ログインなしという要件上、別端末、保存領域削除、トークン再生成を使った重複を完全には防げない。

## エラー処理

- 通信失敗：回答確定状態を推測せず、同じ回答を安全に再送できる案内を出す
- 回答済み：保存済み回答を取得し、同じ選択肢なら結果画面へ、異なる選択肢なら変更不可を案内する
- 公開終了：回答入力を閉じ、終了済み結果画面へ案内する
- ブロック未公開・不存在：公開情報を漏らさず404画面を表示する
- レート制限：再試行まで待つ案内を表示する
- 管理者セッション切れ：未保存内容をブラウザ内に一時保持し、再ログイン後に復元を試みる
- D1障害：回答内容をローカルで確定扱いにせず、再試行可能な状態を維持する

回答ボタンは送信中に多重操作を防ぐが、正しさはUI状態に依存せず、DB制約で保証する。

## モジュール境界

### 参加者Web UI

ブロック一覧、開始・再開、質問、回答結果、振り返りを担当する。APIレスポンスを表示用モデルへ変換し、匿名端末トークンと最後に表示した位置だけをブラウザへ保存する。

### 管理Web UI

ログイン、ブロック一覧、編集フォーム、プレビュー、集計を担当する。公開ルールを事前表示するが、最終検証はAPIへ委ねる。

### Domain

ブロック状態遷移、質問数、選択肢数、文字列正規化、並び順、割合配分など、CloudflareやReactへ依存しないルールを持つ。

### Worker API

ルーティング、認証、CSRF、入力変換、ドメイン処理の呼び出し、D1リポジトリの呼び出し、HTTPレスポンス変換を担当する。

### Repositories

D1へのパラメータ化クエリと行データの変換だけを担当する。状態遷移やアクセス可否を独自判断しない。

この分離により、割合計算や公開ルールをWorker環境なしでテストでき、API統合テストではHTTPとD1制約に集中できる。

## ビジュアルとアクセシビリティ

白に近い温かい背景、濃い墨色、回答を示す暖色を基本とし、展示物を見るような静かな余白を持たせる。一度に一つの問いへ集中できる大きな質問文と、タップしやすい選択肢カードを使う。派手な競争表現やランキング表現は避ける。

回答結果は横棒、人数、割合を併記する。色だけで自分の回答を区別せず、ラベルとアイコンも表示する。キーボード操作、フォーカス表示、適切な見出し、フォームラベル、送信結果の `aria-live` 通知を提供する。主要操作のタップ領域は少なくとも44px相当を確保し、アニメーション低減設定を尊重する。

## テスト方針

### Domain単体テスト

- 1〜10問の境界値
- 2個以上の可変選択肢
- 空白、重複選択肢、文字数、スラッグの検証
- 状態遷移と公開後の不変条件
- 最大剰余法による割合の合計100%

### Worker API統合テスト

- マイグレーション済みD1を使ったブロックCRUD
- 未認証・CSRF不一致の管理操作拒否
- 公開前、公開中、終了後のアクセス制御
- 同一端末・同一質問の重複回答拒否
- 同じ回答の再送を成功扱いにする冪等性
- 同時回答時の一意制約
- 質問と選択肢の所属関係検証
- 回答後だけ公開中の集計を取得できること
- 終了済みブロックの全体集計
- レート制限時のエラー形式

### Reactコンポーネントテスト

- 質問の選択と確認操作
- 送信中、成功、失敗、回答済みの表示
- 人数、割合、自分の選択の表示
- 未回答質問からの再開
- 管理フォームの質問・選択肢追加、削除、並べ替え
- 公開後編集不可の表示

### Playwright E2E

- 管理者がログインし、10問ブロックを作成・公開できる
- 匿名参加者が10問へ回答し、各問の結果と最終振り返りを見られる
- 同じブラウザで再回答できない
- 途中離脱後に最初の未回答質問から再開できる
- 管理者がブロックを終了し、新規回答が拒否される
- モバイル相当幅とデスクトップ幅で主要操作が画面内に収まる

## デプロイと運用

- WranglerでWorkerと静的ファイルを単一デプロイする
- D1マイグレーションをローカルと本番へ適用する手順をREADMEへ記載する
- 管理者パスワードハッシュ、セッション署名Secret、端末ID HMAC SecretをCloudflare Secretとして設定する
- ローカル開発用の秘密値はgit管理外のファイルへ置き、`.env.example`または同等の例だけをコミットする
- サンプルブロック投入を再実行可能なseed処理にする
- 本番URLで一覧、回答、重複防止、集計、管理画面を実ブラウザ検証する
- デプロイ権限やCloudflareアカウント情報が利用できない場合でも、ローカルの本番相当プレビューまで検証できる構成にする。ただし「世界中からアクセスできる」という完成条件は本番デプロイと公開URL確認をもって満たす

## 完成条件

以下のすべてを満たした時点をMVP完成とする。

- `games/minna-no-monosashi/` が他のサブプロジェクトから独立してインストール、開発、テスト、ビルドできる
- 管理者が可変数の選択肢を持つ質問を1〜10問のブロックとして登録できる
- ブロックを公開・終了・複製でき、公開後の質問と選択肢が変更されない
- 匿名参加者が公開ブロックを選び、各質問へ単一回答を1回だけ送れる
- 回答直後に人数・割合を確認でき、全問後にまとめて振り返れる
- 同じブラウザでは途中再開でき、回答済み質問へ再回答できない
- DB制約により同時送信でも重複回答が作成されない
- 終了済みブロックは新規回答を受け付けず、全体集計を公開する
- 管理者画面と回答APIに認証・CSRF・入力検証・レート制限がある
- 個人情報、生の端末トークン、生のIPアドレスをDBや通常ログへ保存しない
- サンプル10問ブロックが利用できる
- 単体、API統合、UI、E2Eテスト、型チェック、プロダクションビルドが成功する
- 実ブラウザでモバイル・PC両方の主要フローを確認できる
- 公開URLへ外部からアクセスし、複数ブラウザの回答が同じ集計へ反映されることを確認できる
