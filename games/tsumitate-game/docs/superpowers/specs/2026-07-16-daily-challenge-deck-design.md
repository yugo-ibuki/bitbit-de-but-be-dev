# 日替わりチャレンジデッキ 設計

## 目的

使用できる物体数を100個のまま維持しながら、全員が同じ条件で挑戦でき、配置、先読み、サイズの使い方によって高さに明確な差が出るゲームへ変更する。

## 日替わりデッキ

日本時間の年月日を`YYYY-MM-DD`形式のチャレンジキーとして使用する。同じチャレンジキーから決定論的な疑似乱数を生成し、その日の100個デッキをブラウザ内だけで作る。ネットワーク通信は使用しない。

デッキの内訳は以下で固定する。

- 形: ボックス34個、ボール33個、シリンダー33個
- サイズ: S30個、M40個、L30個
- サイズ倍率: S=`0.78`、M=`1.0`、L=`1.25`
- 最初の1個: Lサイズのボックス
- 残り99個: ボックス33個、ボール33個、シリンダー33個と、S30個、M40個、L29個を決定論的にシャッフルして組み合わせる

色と初期回転も同じ疑似乱数から決め、同じ日なら全プレイヤーで完全に一致させる。配置する水平座標だけがプレイヤー操作によって変わる。

## プレイ進行

プレイヤーが使用できる物体は常にデッキの現在位置にある1個だけとする。現在の物体を配置すると次へ進む。次の3個は予告として表示するが、順番の変更や選択はできない。

物体を配置した時点で使用数を1増やす。円外へ落ちてシーンから削除されても使用数は戻さない。物体の残存数と使用数を分離し、100回配置した時点でその日のデッキを使い切った状態にする。

「もう一度積む」では、同じ日替わりデッキの先頭から再挑戦する。破壊操作ではデッキ位置を戻さず、壁復活後に残りの物体で積み続けられる。

## 物体サイズと物理

`StackingItem`へサイズ種別と倍率を追加する。描画メッシュとRapierの自動コライダーへ同じ倍率を適用し、見た目と当たり判定を一致させる。落下開始オフセットも倍率に応じて調整し、大きな物体が生成直後に既存物体へめり込まないようにする。

高さ計測では、ボックス、ボール、シリンダーの各半径・半高さへ倍率を適用する。回転後のワールド座標上端を求める既存計算を維持し、S・M・Lすべての実際の最高点を計測する。

## UI

既存の3つの形選択ボタンを削除し、同じ位置にチャレンジデッキパネルを置く。

パネルには以下を表示する。

- `TODAY'S DECK`と日本時間の日付
- 大きく表示した現在の物体: 形アイコン、形名、S・M・L
- 小さく表示した次の3個: 順番、形アイコン、サイズ
- 残りが3個未満の場合は存在する予告だけ表示
- 使い切った場合は`DECK COMPLETE`

物体数表示は`OBJECTS`から`USED`へ変更し、`使用数 / 100`を表示する。シーン内に残る物体数は競争ルールへ使わない。

計測パネルの`PERSONAL BEST`は`TODAY'S BEST`へ変更する。ベスト記録はチャレンジキーごとに保存し、日付が変わると新しい0メートルの記録から始める。以前の日付の記録は表示しない。

デスクトップとモバイルの既存レイアウトを維持し、現在物体と次の3個が操作説明や破壊ボタンと重ならないようにする。

## 状態とデータフロー

- `createDailyChallengeDeck(challengeKey)`が100個の決定論的デッキを返す
- `App`は起動時の日本時間チャレンジキーとデッキを保持する
- `GameState`は`usedCount`を保持し、配置成功時だけ1増やす
- `App`は`deck[usedCount]`から現在物体を生成する
- `remove`はシーン内の物体だけを削除し、`usedCount`を変更しない
- `reset`は物体を空にし、`usedCount`を0へ戻す
- `destroy`と壁復活は`usedCount`を変更しない
- `GameHud`は現在物体、次の3個、使用数、チャレンジ日付を受け取る

## 保存

ベスト記録の保存キーへチャレンジキーを含める。不正な値、負数、無限値、ストレージ例外を0として扱う既存の安全策は維持する。

日付が変わった状態でページを開き続けた場合、その実行中のデッキは変えない。リロードまたは再起動時に新しい日本時間の日付を読み、新しいデッキとベスト記録へ切り替える。

## エラーと境界条件

- 100個使用後の配置操作では物体を生成せず、`本日の100個を使い切りました`と表示する
- 次の3個が100個の末尾を超える場合は存在する物体だけ表示する
- 物体が円外へ落ちても同じデッキ位置を再利用しない
- 破壊後もデッキ順と使用数を維持する
- リセット時はベスト記録を維持する
- 日本時間のチャレンジキー生成に失敗した場合は、同じ時刻のUTC日付を`YYYY-MM-DD`形式で使用してゲームを継続する

## テスト

- 同じ日付から同じ100個を生成する
- 異なる日付から異なる並びを生成する
- 形とサイズの個数が指定どおりになる
- 先頭がLボックスになる
- 色と初期回転が同じ日付で一致する
- サイズ倍率が描画、コライダー、高さ計測へ反映される
- 配置で`usedCount`が増える
- 落下削除で`usedCount`が減らない
- 100個使用後は配置できない
- リセットで`usedCount`が0へ戻る
- 破壊と壁復活で`usedCount`が変わらない
- チャレンジキーごとに別のベスト記録を保存する
- HUDが現在物体、次の3個、使用数、日付を表示する
- デスクトップとモバイルの実ブラウザでUIの重なりがない

## 対象外

- デッキコードによる共有
- オンラインランキング
- プレイヤー名やアカウント
- 次の物体の入れ替え、スキップ、選択
- 日付変更時の自動リロード
- 過去の日別記録一覧

## 完了条件

- 日本時間の同じ日付で全員同じ100個デッキになる
- 現在の1個と次の3個が明確に表示される
- S・M・Lが見た目、物理、高さ計測へ一致して反映される
- 落下しても100個の消費数が戻らない
- 日替わりベスト記録がリロード後も維持される
- 自動テスト、型チェック、本番ビルドが成功する
