### 静的確認で分かったこと

- 方向入力の初回押下時に16pxの衝突判定付き移動を即時反映し、キーリピートまたは押下済み入力では即時移動を重ねない。
- 押下状態は従来どおり ticker で読み続けるため、長押し中は毎秒168pxの連続移動を行う。
- 矢印キーとモバイル方向ボタンは手動照準を解除し、移動方向へライトを向ける。
- ポインター照準はプレイ中のゲームキャンバス上の移動だけで有効になり、開始前オーバーレイ上のホバーでは有効にならない。
- 開始とリスタートでは、入力状態と手動照準を初期化する。

### 改善後も実ブラウザで未確認の項目

- 矢印キーとモバイル方向ボタンを長押ししたときの継続移動。
- 改善後のコードでヒューズ3個を実回収して勝利する一連の操作。敗北と `TRY AGAIN` によるリスタートは改善前に確認済みで、改善後は開始直後の `TRY AGAIN` から移動できることを確認した。

## ロジックテストで確認した内容

- 外周と内部の壁セルを判定する。
- 円形のプレイヤーが壁を通過せず、壁沿いには移動できる。
- 範囲内のヒューズだけを回収する。
- 3個すべての回収後だけ出口を解錠する。
- 施錠中の出口では勝利せず、解錠後の出口で勝利する。
- 追跡者と接触すると敗北する。
- 追跡者からプレイヤーまでと、開始地点から全ヒューズ・出口まで、壁を避けた経路が存在する。

## 実装上の観察

- PixiJS v8 の非同期 `Application.init()` と `Graphics` を使い、外部画像なしで全景を描画した。
- 追跡者は一定間隔で幅優先探索をやり直し、開口部を通るセル単位の経路を追う。
- プレイヤーは追跡者より速く、追跡開始まで3.5秒の猶予がある。ヒューズ回収に応じて追跡速度が少し上がる。
- 描画解像度は device pixel ratio 1.75 以下に制限し、`ResizeObserver` でゲーム世界を画面内へ収める。
- ローカルフォントとベクター描画だけを使用し、実行時に外部素材を取得しない。
- ソース内の URL を検索し、インラインのノイズ用 SVG データ URI 以外に HTTP(S) URL がないことを確認した。

## 観察した失敗と対応

- 最初の `npm install` は npm 11.5.1 の依存木処理中に `Cannot read properties of null (reading 'edgesOut')` で失敗した。依存バージョンを実在する固定値へ揃え、`npm install --legacy-peer-deps` で再実行すると成功した。
- 最初の型検査とビルドは未使用 import 1件で失敗した。未使用 import を削除した後、型検査とビルドを再実行して成功を確認した。
- 最初のブラウザ目視では懐中電灯の円錐が背景と区別しにくかった。暗幕の不透明度を下げ、円錐へ薄い発光色を加えた後、ポインター方向の光を目視確認した。

## 未確認事項

- ポインター移動に応じた光の方向変更はコード上のイベント処理と静止画の光円錐を確認したが、連続操作の見た目は未確認。
